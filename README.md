# 🏠 My Homelab Docker Setup

Моя домашняя лаборатория. Проект для себя, где настроены маршрутизация, скачивание, VPN, сетевое хранилище, локальный DNS без рекламы и полноценный стек мониторинга.

---

## 🗺 Карта сервисов и маршрутизация

Вся лаборатория теперь работает через единую точку входа (Nginx Proxy Manager) и локальный DNS-сервер (AdGuard Home). Вместо IP-адресов и портов используются красивые и безопасные домены.

### 🌐 Сеть и Управление
| Сервис                  | Назначение                                      | Внутренний Доступ          | Заметки                             |
| :---------------------- | :---------------------------------------------- | :------------------------- | :---------------------------------- |
| **Nginx Proxy Manager** | Реверс-прокси, выдача SSL сертификатов          | `http://<IP_СЕРВЕРА>:81`   | Распределяет трафик по контейнерам  |
| **AdGuard Home**        | Локальный DNS (Split-DNS) и блокировщик рекламы | `http://<IP_СЕРВЕРА>:8085` | Порт 53/udp раздает DNS на всю сеть |
| **DuckDNS**             | Динамический DNS                                | Работает в фоне            | Обновляет внешний IP для домена     |

## 🚀 Порядок развертывания с нуля

### Шаг 1. Подготовка системы (Важно!)
Перед запуском контейнеров необходимо освободить порт `53`, чтобы AdGuard Home мог работать как локальный DNS-сервер, и добавить пользователя в группу `docker`, чтобы не использовать `sudo` (иначе папки создадутся в `/root`).

```bash
# 1. Добавляем пользователя в группу docker (потребуется перезаход в систему)
sudo usermod -aG docker $USER

# 2. Проверяем слушает ли порт 53:
ss -tulpn | grep :53

# Вывод должен быть пустой, если нет, то скорее всего он занят systemd-resolved
```

### Шаг 2. Запуск проекта
1. **Клонировать репозиторий:**
   ```bash
   git clone https://github.com/Leschock-Syu/homelab-docker
   cd homelab-docker
   ```
2. **Настроить секреты:**
   ```bash
   cp .env.example .env
   nano .env
   ```
3. **Запустить всё (теперь можно без sudo):**
   ```bash
   docker compose up -d
   cd monitoring && docker compose up -d && cd ..
   ```

## 🔧 Шпаргалка по управлению

**Управление контейнерами:**
```bash
# Остановить весь стек
docker compose down

# Перезапустить один зависший контейнер
docker compose restart qbittorrent

# Посмотреть логи в реальном времени
docker compose logs -f amneziawg-easy

# Проверить потребление ресурсов
docker stats
```

## 🔔 Настройка уведомлений в Uptime Kuma

Для получения алертов о падении сервисов проще всего использовать **Ntfy** (работает без проблем и блокировок):

1. Установите приложение Ntfy на телефон и создайте подписку (любое уникальное имя).
2. В Uptime Kuma откройте **Настройки** (в правом верхнем углу) -> **Уведомления** -> **Создать**.
3. **Тип уведомления:** Ntfy.
4. **URL сервера Ntfy:** `https://ntfy.sh/<имя_вашей_подписки>`.
5. Нажмите "Тест" — на телефон должно прийти пуш-уведомление.

### Как добавлять сервисы в мониторинг (New monitor):
Теперь, когда настроен локальный DNS, мы мониторим сервисы по их доменным именам!

**Для веб-сервисов (например, Grafana):**
- **Тип монитора:** HTTP(s)
- **Имя:** Grafana
- **URL-ссылка:** `https://<ваш_придуманный_домен>`

**Для систем без веба (например, Samba):**
- **Тип монитора:** TCP Port
- **Имя:** Samba
- **Имя хоста:** `192.168.0.129` (ваш локальный IP)
- **Порт:** `445`
